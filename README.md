# Проект: Категории и Товары (ООП и тестирование)

Данный проект реализован в рамках изучения объектно-ориентированного программирования (ООП) на Python. Включает в себя создание базовых классов, работу с атрибутами класса, парсинг данных из JSON и полное покрытие кода модульными тестами.

## Архитектура проекта

```
PythonProject4/
├── src/                    # Исходный код проекта
│   ├── __init__.py
│   ├── main.py             # Описание классов Product и Category
│   └── utils.py            # Вспомогательные функции (загрузка из JSON)
├── tests/                  # Директория с тестами
│   ├── __init__.py
│   ├── test_main.py        # Тесты инициализации классов и счетчиков
│   ├── test_utils.py       # Тесты функции загрузки JSON
│   └── test_data.json      # Фиктивные данные специально для тестов
├── products.json           # Реальный файл с данными
└── README.md
```

## Основной функционал

### Классы (`src/main.py`)
* **`Product`**: Экземплярный класс для представления товара. Содержит свойства: название, описание, цена, количество.
* **`Category`**: Класс для представления категории товаров.
  * Имеет **атрибуты класса** (`category_count`, `product_count`), которые автоматически инкрементируются при каждом вызове `__init__`. Это позволяет хранить общую статистику по всем созданным объектам без дополнительных функций подсчета.
  * Использована аннотация типов (Type Hinting) для улучшения читаемости кода.

### Загрузчик данных (`src/utils.py`)
* Функция `load_json_data()` безопасно читает файл (с учетом кодировки `utf-8`), проходит циклом по вложенной структуре и динамически создает объекты `Product` и `Category`.

## Тестирование

Проект покрыт Unit-тестами с использованием фреймворка `pytest`. Покрытие составляет более 85%.

**Особенности тестов:**
* **Изоляция состояния:** Использована фикстура с `autouse=True` и оператором `yield`. Она автоматически сбрасывает атрибуты класса (`category_count` и `product_count`) до и после каждого теста. Это предотвращает влияние тестов друг на друга при параллельном или последовательном запуске.
* **Независимость от реальных данных:** Для тестирования парсинга JSON создан отдельный файл `test_data.json` в папке `tests`, чтобы тесты не ломались при изменении основного файла.
* **Использование `pathlib`**: Пути к файлам в тестах строятся через `Path(__file__).parent`, что делает тесты кроссплатформенными (работающими на любой ОС).

## Запуск проекта

### Запуск основного скрипта
Для вывода данных в консоль выполните:
```
python -m src.main
```
*(или просто запустите файл `main.py` через вашу IDE)*

### Запуск тестов
Для запуска всех тестов перейдите в корневую папку проекта и выполните:
```
pytest
```

### Запуск тестов с отчетом о покрытии кода
*(Требуется установка пакета: `pip install pytest-cov`)*
```
pytest --cov=src tests/
```
