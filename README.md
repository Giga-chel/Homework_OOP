# Проект: Категории и Товары (Продвинутое ООП и тестирование)

Данный проект реализован в рамках глубокого изучения объектно-ориентированного программирования (ООП) на Python. Включает в себя проектирование архитектуры с использованием абстрактных классов (ABC), миксинов (Mixins), сложного множественного наследования (MRO), а также полное покрытие кода модульными тестами с использованием мокирования и перехвата потоков ввода/вывода.

## Основной функционал

### Классы (src/main.py)

**Базовые сущности и миксины**
*   **`BaseProduct(ABC)`**: Абстрактный базовый класс для всех продуктов. Задает контракт (через `@abstractmethod`), запрещая прямое создание экземпляра. Содержит "продувную трубу" `__init__(*args, **kwargs)` для безопасного завершения цепочки множественного наследования.
*   **`MixinProduct`**: Класс-миксин. Подмешивается в цепочку наследования для перехвата аргументов при инициализации и вывода информации о создании объекта в консоль в формате `ClassName('arg1', 'arg2')`.
*   **`BaseEntity(ABC)`**: Общий абстрактный класс для сущностей, обладающих именем (используется как предок для `Category` и `Order`).

**Товары**
*   **`Product(MixinProduct, BaseProduct)`**: Основной класс товара. Реализует сложную цепочку MRO. Содержит приватный атрибут `__price` с декоратором `@property` для защиты от некорректного назначения цен (включая интерактивное подтверждение снижения цены).
    *   `new_product`: Класс-метод для фабричного создания товаров или обновления существующих.
    *   `__add__`: Перегрузка оператора для сложения стоимости товаров одинакового типа.
*   **`Smartphone` и `LawnGrass`**: Дочерние классы, расширяющие `Product` специфичными атрибутами. Лишние атрибуты "оседают" в них и не передаются в миксин.

**Заказы и Категории**
*   **`Order(BaseEntity)`**: Класс заказа. Использует композицию (хранит ссылку на объект `Product`). Итоговая стоимость вычисляется "на лету" через `@property total_cost`.
*   **`Category(BaseEntity)`**: Класс для управления группой товаров. Реализует протокол итерации за счет связки с `CategoryIterator`.
*   **`CategoryIterator`**: Кастомный итератор для безопасного обхода приватного списка товаров `__products`.

### Загрузчик данных (src/utils.py)
Функция `load_json_data()` безопасно читает файл (с учетом кодировки `utf-8`), проходит циклом по вложенной структуре и динамически создает объекты `Product` и `Category`.

## Примеры использования

```python
from src.main import Category, Smartphone, Order

# При создании любого продукта срабатывает миксин и печатает:
# Smartphone('Samsung Galaxy S23', '256GB', 180000.0, 5, 95.5, 'S23', 256, 'Серый')
phone = Smartphone("Samsung Galaxy S23", "256GB", 180000.0, 5, 95.5, "S23", 256, "Серый")

category = Category("Смартфоны", "Современные телефоны")
category.add_product(phone)

print(category)  # Смартфоны, количество продуктов: 5 шт.
print(phone)     # Samsung Galaxy S23, 180000.0 руб. Остаток: 5 шт.

# Создание заказа на основе существующего товара (композиция)
order = Order("Заказ #1", phone, 2)
print(order.total_cost)  # 360000.0 (вычисляется динамически)

# Итерация по товарам категории
for product in category:
    print(product.name)
```

## Тестирование

Проект покрыт Unit-тестами с использованием фреймворка `pytest`. Покрытие кода составляет **98-100%** (исключая служебные функции вывода через `# pragma: no cover`).

**Особенности тестов:**
*   **Изоляция состояния:** Использована автозапускаемая фикстура (`autouse=True` с `yield`) для сброса классовых счетчиков (`category_count`, `product_count`).
*   **Проверка абстракций и типов:** Использование `pytest.raises(TypeError)` для проверки невозможности создания `BaseProduct` и отказа от добавления невалидных объектов в категорию.
*   **Тестирование побочных эффектов (stdout):** Использование встроенной фикстуры `capsys` для перехвата вывода миксина и проверок сеттера цены.
*   **Мокирование (Mocking):** Использование `unittest.mock.patch` для подмены функции `input()` при тестировании логики подтверждения снижения цены.
*   **Независимость от реальных данных:** Пути к файлам строятся через `pathlib.Path`, тесты используют изолированный `test_data.json`.
